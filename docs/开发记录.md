## 0. 背景与目标

- **目标**：为 RSYWX 个人图书馆 / 博客重建一个“快”的前端。
- **两点关键澄清**（详见第 4 节）：
  1. 站点**本质是动态的**（内容依赖实时 API），因此**排除纯静态 / SSG** 方案。
  2. 所谓“快”指**运行时性能**（JS 体积、渲染与导航速度），**不纠结**跨国网络连通性——
     站长通常经 VPN 访问，故不把“中国↔境外延迟 / 海外 CDN / ICP 备案”作为设计目标。

## 1. 后端（api.rsywx.2026）评审

### 1.1 技术栈与形态

- PHP ≥ 8.0 + **Slim 4** + PSR-7（`slim/psr7`）+ `vlucas/phpdotenv` + `zircote/swagger-php`。
- 入口 `public/index.php` → `config/env.php` + `config/app.php`；**路由与中间件都在 `config/`**，
  生产与 PHPUnit 测试共用同一套装配，保证“测试即生产”。
- 部署：Apache 虚拟主机指向 `public/`。
- OpenAPI 规格由控制器注解**按需生成**（`/api-docs.json`、`/api-docs.yaml`，ReDoc 在 `/`）。

### 1.2 横切关注点

- **鉴权**：`X-API-Key` 头（推荐）或 `?api_key=` 查询参数，使用 `hash_equals` 恒定时间比较。
  豁免：`/`、`/health`（含 `/api/v1/health`）、`/api-docs*`、`OPTIONS`。失败返回 **401**。
- **CORS**：全开（`Access-Control-Allow-Origin: *`），`OPTIONS` 预检返回 200；错误响应也带 CORS 头。
- **错误封装**：统一 `{ "success": false, "message": "...", ["detail": "..."] }`。
  状态码映射：`ApiException`→自身码、Slim `HttpException`→404/405、`InvalidArgumentException`→400、其他→500。
- **成功封装**：`{ success, data, cached [, message] [, pagination] [, 附加字段] }`；
  缓存类端点支持 `?refresh=true` 强制重算。
- **缓存**：APCu 优先，环境不支持时退化为文件缓存；`POST /admin/cache/clear` 清理。

### 1.3 端点清单（共 30 条路由）

- **System**：`GET /`（ReDoc）、`GET /api-docs.json|.yaml`、`GET /health` 与 `GET /api/v1/health`、
  `POST /api/v1/admin/cache/clear`。
- **Books**：`status`、`{bookid}`、`latest[/{count}]`、`random[/{count}]`、`last_visited[/{count}]`、
  `forgotten[/{count}]`、`popular/{count}`、`unpopular/{count}`、`today[/{month}/{date}]`、
  `visit_history`、`list[/{type}[/{value}[/{page}]]]`、`POST {bookid}/tags`、`{bookid}/related`（PENDING）。
- **Misc**：`wotd`、`qotd`、`weather/current`、`weather/forecast`。
- **Readings**：`summary`、`latest[/{count}]`、`reviews[/{page}]`。
- **Blog**：`today[/{month}/{day}]`、`latest[/{count}]`（读取 WordPress 库）。

### 1.4 关键观察

- `GET /books/{bookid}/related` 已注册路由，但文档标注 **PENDING（未实现）**。
- `books/list` 的 `value` 为 catch-all 段（可包含 URL 编码的斜杠 / 百分号）。
- 详情响应对 `translated` 转为布尔、`price` 转为浮点（涉及线类型统一，见 INT-07）。

## 4. 关键决策过程（问答记录）

> 以下按对话顺序记录“我提出的问题 → 站长给出的决定 → 结论与理由”。

### 4.1 目标目录为空 → 绿地重写

- 现状：`/home/tr/www/rsywx` 为空；存在旧前端 `rsywx.svelte.2025`。
- **决定**：**绿地重写**（不迁移旧代码），旧项目仅作约定参考。
- 理由：技术栈要升级到 SvelteKit 3，迁移成本不划算；绿地能一次到位。

### 4.2 对“快”的理解 → 忽略连通性，聚焦运行时性能

- 起初我按“中国访问境外站点延迟”方向研究（CDN / ICP 等）。
- **站长澄清**：“不要和连通性混为一谈……我大多通过 VPN 访问，就当忽略连通性。”
- **结论**：“快”指**应用运行时性能**（更少的 JS、更快的渲染与导航、更快的交互），
  **不**以网络延迟 / CDN / 备案为目标。

### 4.3 站点本质是动态的 → 排除纯静态 / SSG

- **站长**：“站点与 API 后端天然是动态的，静态站无法满足需求。”
- **结论**：采用 **SSR（服务端渲染）/ 动态**方案，排除纯静态生成（SSG）。

### 4.4 框架调研与选型结论

- 调研对象：**Astro 7**、**SvelteKit 3**、**Qwik（可恢复性）**、**Next.js**、**Nuxt**。
- 结论：**SvelteKit 3 最合适**——
  - Svelte 编译为直接 DOM 更新，运行时很小；SvelteKit 是轻量的 SSR 应用框架。
  - 与站长偏好的 **Svelte + Tailwind + shadcn-svelte** 组合天然契合。
  - **唯一“更极致”的候选是 Qwik**（可恢复性，交互前近乎零 JS），但要放弃 Svelte 组件与 shadcn-svelte、
    生态更小，收益在“现代浏览器 + VPN”场景下并不值得。
  - Astro 的优势在“以静态内容为主 + 少量岛屿”，对本“处处动态”的应用不如 SvelteKit 自然；Next/Nuxt 偏重。

### 4.5 技术栈锁定

- **决定**：**SvelteKit 3 + Svelte 5（runes）+ Tailwind CSS 4 + shadcn-svelte，SSR / 动态**。
- 版本（对话时）：SvelteKit **3.1**、Svelte **5.57**、Tailwind **4.3**、Vite **8.3**、`@sveltejs/adapter-node` **6.0**。
- 要点：SvelteKit 3 把**配置移到 `vite.config.ts`**，`$lib` 别名改为 **`#lib`**，环境变量改用 **`defineEnvVars`**
  （旧的 `$env/static/private`、`$app/environment` 在 3.x 已废弃）。

### 4.6 首轮范围

- **决定**：**T0（基础）+ T1（核心）**，即“先做一条打通全栈的纵切”，再扩展：
  - T0：脚手架、`env`、主题 / 样式、布局（页头 / 页脚 / 主题切换）、API 客户端 + 类型 + 错误处理、SEO。
  - T1：**首页**、**书籍详情**、**检索 / 列表**、**读书**。
  - T2（待办）：书籍发现页（随机 / 今日往昔 / 热门 / 冷门 / 被遗忘 / 最近浏览 / 访问记录）、博客页、天气组件。

### 4.7 默认取舍（均可按需调整）

- **语言**：界面保持**简体中文（zh-CN）**。
- **视觉**：**复用旧站观感**（oklch 调色板、深浅色、渐变分隔标题），做“精修”而非“重设计”。
- **封面**：由**前端**从 `/covers/{bookid}.jpg` 提供（与后端 INT-05 结论一致）。
- **开发后端地址**：指向本地后端；本地 `:8000` 被其他程序占用，故实际使用 **`:8010`**。

## 5. 架构设计

### 5.1 目录结构（`/home/tr/www/rsywx`）

```
vite.config.ts            # SvelteKit 3：kit 配置 + Tailwind 插件 + adapter-node
tsconfig.json             # 继承 $app/tsconfig，并为 #lib 增加 paths 映射
src/
  env.ts                  # defineEnvVars：RSYWX_API_KEY / RSYWX_API_BASE_URL（服务端）
  app.html                # lang=zh-CN；含“防闪烁”主题初始化脚本
  app.css                 # Tailwind 4 + oklch 主题变量 + 深色变体
  lib/
    server/api/           # 仅服务端：client.ts（apiFetch/ApiError）、endpoints.ts（各端点函数）
    types/api.ts          # 后端响应契约类型
    config/site.ts        # 站点信息（名称/SEO/外链）
    config/media.ts       # 封面 URL 助手
    components/           # book-card / section-heading / seo / theme-toggle / layout / ui(card,button)
    utils.ts              # cn() 等
  routes/
    +layout.svelte  +error.svelte
    +page.server.ts  +page.svelte                      # 首页
    books/+page.ts                                      # /books → /books/list
    books/[bookid]/+page.{server.ts,svelte}             # 书籍详情
    books/list/[[type]]/[[value]]/[[page]]/+page.{server.ts,svelte}   # 检索 / 列表
    readings/[[page]]/+page.{server.ts,svelte}          # 读书
    api/visit/[bookid]/+server.ts                       # 记录访问（BFF）
static/images/logo.svg
```

### 5.2 环境变量与密钥（关键安全点）

- 使用 SvelteKit 3 的 `src/env.ts` + `defineEnvVars({...})`，通过**继承 `$app/env/private`** 读取。
- `$app/env/private` 是**服务端专用模块**；`#lib/server/api/*` 位于 `server/` 目录，同样被 SvelteKit 强制为服务端。
- **API Key 永不进入浏览器打包产物**。浏览器侧的“刷新”类调用走同源的 `/api/*`（BFF），由服务端持有密钥。

### 5.3 服务端数据层

- `#lib/server/api/client.ts`：`apiFetch()` 负责拼接 URL、注入 `X-API-Key`、解析 `{success,data,cached}`
  封装，并在非 2xx 时抛出携带状态码的 **`ApiError`**（失败不会被误当作“空数据”）。
- `#lib/server/api/endpoints.ts`：**每个端点一个类型化函数**，是 API 调用的唯一出处。

### 5.4 渲染与性能策略（“快”的落点）

- 全部页面 **SSR**（动态）；无预渲染。
- `+page.server.ts` 中**并行**发起独立请求（`Promise.all`），并对每个部件**隔离失败**，
  单一端点故障不会导致整页空白。
- 可缓存路由通过 `setHeaders()` 下发 `Cache-Control`（配合后端 24h 缓存），让上游代理吸收重复请求。
- `app.html` 的 `<body data-sveltekit-preload-data="hover">`：悬停预取，导航更快。
- 依赖克制：暂不引入 embla 轮播等重依赖；组件用 shadcn-svelte 拷贝式组件，无运行时 UI 库。

### 5.5 错误处理

- **每个分区可降级**（部件级错误提示），另有 `+error.svelte` 全局错误页。
- 页面 load 中把 `ApiError` 映射为 SvelteKit 的 `error(status, message)`，保留后端语义状态码。

### 5.6 访问记录（落实后端 INT-03）

- 详情页服务端 **只读**加载（`?visit=false`），**不在悬停预取 / 刷新时计数**。
- 浏览器在页面真正挂载（`onMount`）后调用 `POST /api/visit/[bookid]`，由 BFF 服务端补记一次访问。
  —— 悬停预取不会挂载组件，因此不会误记。

## 10. 版面重构：「今日一页」报纸版式（2026-11-08）

- **起因**：T1 实现的版面与线上旧站（rsywx.net）过于相似——相同的顶部导航、居中 Hero 轮播、
  居中渐变分节条、三列卡片区与三列页脚。站长要求更彻底的版式创意。
- **决策**：首页改为**一张报纸头版**。报头（报名 + 题铭「有之以为利，无之以为用」+ 双细线日期栏：
  第 N 年 · 第 N 期，自 1989 年起算，期号 = 当日为该年第几天）、头版照片（全页唯一彩色 + 极淡网点）、
  头条「今日往昔」（首字下沉 + CSS 多栏排文）、右栏为加框边栏（书讯 / 藏书统计点线账目 /
  每日一词 / 每日一句）；「手气不错」为头版图版下的封面橱窗条（六册并排、灰度、可换一批），
  由 `lucky-shelf.svelte` 渲染（原分类广告式表格 classifieds.svelte 已移除）。
  内页统一以「部门头 + 双细线」开篇。
- **设计系统**：新闻纸底色 + 暖墨色 + 细线（hairline rules）+ 单一专色朱砂；CJK 宋体栈（零 Web 字体
  成本）、账目数字用等宽字体；`--radius: 0`（全站无圆角）；纸纹以 SVG feTurbulence 平铺于 `<html>`。
  shadcn 令牌（background/foreground/border/…）整体重映射到报纸色板，vendored 组件自动继承。
- **色彩策略**：通篇黑白（新闻纸 + 暖墨）以体现厚重；头版照片是**唯一的彩色元素**
  （《辛德勒的名单》式的 selective colour），封面缩略图一律灰度、悬停方才显色——
  颜色只出现在「头版」与「目光所及」两处。
- **藏书总目（/books/list）**：纯列表，一册一行，每页 20 册（后端 `LIST_PER_PAGE=20`）；
  行内依次为 编号（等宽）/ 书名（宋体加粗，点击进详情）/ 地区·著者·译者 / 架位（等宽）；
  **著者**是链接，指向该作者的检索（`authorSearchUrl`），**译者**为纯文本；检索类型
  （书名/著者/标签/其他）在选中时以**朱砂实底 + 纸色字**的戳记样式高亮，并带 `aria-pressed`；桌面端有双细线
  列头，移动端折行为「编号 书名 架位」＋「著者」，无封面图。`book-card.svelte` 随之删除。
- **书详情（/books/{bookid}）**：封面**常彩、满幅、不裁切**——所有封面均为 600px 宽、高度不等，
  故宽度跟随左栏（md 300px / lg 340px）、高度随图原比例；封面下以**朱砂大写等宽「架位」戳记**
  （如 `f4`）标示，图注 `mt-auto` 钉在列底，使图版列与右侧卡片**底边精确齐平**。
  右栏为带细线框的目录卡：`【地区】`+ **著者（链接，指该作者检索）** + 译者（纯文本）、
  点线账目（编号/出版社/出版地/ISBN/分类/版次/装帧/页数/字数/定价/购买日/出版日），
  卡片底部固定「访问 N 次 · 最近 YYYY-MM-DD HH:MM」（含时刻）+ 标签；
  其下**「简介」与「书评」同排一行**（lg 起 `0.85fr / 1.15fr`，实测 493px + 667px）——
  简介占据自己的阅读栏（约 30–35 字/行），右侧空白由书评填满，短简介不再孤悬左角；
  简介按换行分段、段首缩进 2em；无简介时书评横跨整幅；书评无内容时显式给出空状态。
- **标签编辑（书详情）**：标签行右侧带输入框，**仅以空格分隔**（含全角空格；逗号、顿号不再切分，
  于是 `x,y` 就是一个标签），提交走 `POST /api/tags/{bookid}` → 后端 `POST /books/{bookid}/tags`
  （**只追加**，已存在的回在 `duplicate_tags`），返回后本地列表即时插入并提示「已添加 / 已存在」。
  **超限不静默丢弃**（方案 A）：前端按同一套上限（≤10 个、单个 ≤30 字）先行分流，只提交合法项，
  提示里逐条列出「已忽略 —— 超长：…；超出 10 个：…」；全部不合法则不发请求。
  写路径的三道约束：① `RSYWX_TAG_EDIT`（默认 on，置 off 则连路由一起关死）；
  ② 同源校验（带外站 `Origin` 的 POST 直接 403）；③ 服务端上限同上，作为兜底。
  另：后端 `book_detail_{id}` 缓存 24 小时**且写入不失效**，故写成功后由服务端尽力调用
  `/admin/cache/clear`，保证刷新即见新标签（缓存清理失败不影响写入结果）。
  未入架记录（`location` 为 `--`/`na`）本就整页 404，读与写均给出中文说明。
- **字号层级（kicker 类）**：栏目标题/框头/页脚栏头/页级眉标一律 **12px 等距等宽**（原 11px 偏小）；
  正文内的微标签（架位、标签、新入库、同日其他文章、其他书评：）保持 **10px**，作为刻意压低的注释；
  详情页「简介」不再用 11px 的 h2，而是与「书评」同构的 SectionHead（眉标 12px + 宋体标题 28px）。
- **右栏**：顺序为 天气 → 藏书统计 → 书讯 → 每日一词 → 每日一句。天气取
  `/misc/weather/current`（温度/体感 + 湿度/气压/能见度/风速 点线账目，head 标更新时刻）；
  「每日一词 / 每日一句」各带「换」按钮，经 `/api/wotd`、`/api/qotd` 代理取新随机条
  （后端本就每次请求随机，无缓存），请求中按钮呈旋转态、失败只在该框内提示、不破坏已有内容。
- **书评索引**：首页只有一档「最新书评」（取最新 8 篇，单档呈现）：导语一篇（大标题 +
  细线副题行：朱砂相对时间 / 刊出日 / 评《书》+ 图版 + 导语段），其余全部收进
  一条中点分隔的流式行「其他书评：」（条目用相对时间且「题名＋时间」以 inline-block 原子化
  防孤行）；日期取博客 permalink 的刊出日（`datein` 仅回退），列表在页面负载时显式倒序。
  图版为**叠印**：本地封面即时付印（SSR 不等远端图），笔记自带配图 onload 后淡入叠上，
  慢或缺时封面常在，图版永不空印；栏头 meta 只留事实（累计 N 篇 / 第 4–8 篇）。
- **手气不错**：封面橱窗条（六册并排、灰度、可换一批）置于**头版图版正下方**，
  由 `lucky-shelf.svelte` 渲染（原分类广告式表格 classifieds.svelte 已移除）。
- **日期与头版照片**：在 `+page.server.ts` 内以站点时区（Asia/Shanghai）计算期号并据此选片，
  SSR 与客户端始终一致，不需客户端 JS。
- **删除的旧组件**：`hero`、`section-heading`、`stat-tile`、`reading-item` 及 `home/` 下的
  status-card、latest-book、last-visited、reading-list-card、reading-summary、random-books、
  word-of-the-day、quote-of-the-day、blog-today；新增 `paper/`（section-head、page-head、box、
  brief、ledger）与 `home/`（masthead 配套的 today-column、review-column、news-briefs、
  library-ledger、daily-boxes、classifieds）及 `layout/masthead`、`layout/front-photo`。
  头部改为「folio bar」细条导航，页脚改为版权页（colophon）。
- **验证**：`lint` / `check`（0 错 0 警）/ `build` 通过；真实后端下逐路由 200；
  360–1440px 六个断点均无横向溢出；换一批、主题开关、暗色令牌经无头浏览器实测。
